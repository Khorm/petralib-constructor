# Smoke Tests (Дымовые тесты)

## Что такое Smoke Tests?

Smoke тесты - это быстрые базовые тесты для проверки критически важной функциональности приложения. Они должны проходить, чтобы приложение считалось работоспособным.

## Цель Smoke Tests

Проверить, что:
- ✅ Приложение запускается
- ✅ API доступно
- ✅ Аутентификация работает
- ✅ Основные endpoints отвечают
- ✅ База данных доступна
- ✅ Безопасность работает (endpoints защищены)

## Список Smoke Tests

### ST001: Приложение запускается и API доступно
- Проверяет, что можно сделать запрос к API
- Даже 401 ответ означает, что приложение работает

### ST002: Аутентификация работает
- Проверяет, что можно получить JWT токен через `/api/v1/auth/login`
- Проверяет структуру ответа (token, email)

### ST003: Защищенные endpoints требуют авторизацию
- Проверяет, что без токена возвращается 401
- Проверяет несколько критичных endpoints

### ST004: С валидным токеном можно получить список проектов
- Проверяет базовую функциональность получения данных
- Проверяет, что токен работает

### ST005: С валидным токеном можно получить текущего пользователя
- Проверяет работу с пользовательскими данными
- Проверяет структуру ответа

### ST006: Можно создать проект
- Проверяет функциональность создания данных
- Проверяет, что создание возвращает 201 Created

### ST007: Login endpoint доступен без авторизации
- Проверяет, что login публичный (не требует токена)

### ST008: Неверные учетные данные отклоняются
- Проверяет безопасность (неверные данные -> 403)

### ST009: База данных доступна
- Проверяет, что можно получить данные из БД
- Косвенно проверяет подключение к БД

### ST010: API возвращает правильные HTTP статусы
- Проверяет корректность HTTP статусов (200, 401, 403)

## Запуск Smoke Tests

### Через Gradle

```bash
# Запустить только smoke тесты
./gradlew test --tests SmokeTest

# Или все автотесты (включая smoke)
./gradlew testAuto
```

### Через IDE

1. Откройте `SmokeTest.java`
2. Запустите все тесты в классе (Ctrl+Shift+F10 в IntelliJ)

## Время выполнения

Smoke тесты должны выполняться быстро (< 10 секунд), так как они проверяют только критичную функциональность.

## Когда запускать Smoke Tests

- ✅ После каждого деплоя
- ✅ Перед запуском полного набора тестов
- ✅ В CI/CD pipeline как первый этап
- ✅ После изменений в конфигурации
- ✅ После изменений в базовых компонентах (Security, Database)

## Критерии успеха

Все smoke тесты должны проходить для того, чтобы:
- Приложение считалось работоспособным
- Можно было переходить к более детальному тестированию
- Можно было деплоить в production

## Если Smoke Test падает

Если хотя бы один smoke test падает:
1. ❌ Приложение НЕ готово к использованию
2. ❌ Нужно исправить проблему перед продолжением
3. ❌ Не запускать полный набор тестов (экономия времени)

## Расширение Smoke Tests

При добавлении новой критичной функциональности:
1. Добавьте соответствующий smoke test
2. Убедитесь, что тест быстрый (< 1 секунды)
3. Убедитесь, что тест проверяет только критичную функциональность

## Связь с другими тестами

```
Smoke Tests (10 тестов, < 10 сек)
    ↓ (если проходят)
Auto Tests (45+ тестов, ~1-2 мин)
    ↓ (если проходят)
Manual Tests (24 теста, ~30-60 мин)
```
